# 一键隐私模式与受限时段设计

日期：2026-10-08
状态：已按用户确认的方案实现；Windows 原生、OpenGL 合成及全仓回归已通过。macOS/Linux 原生隐私验收未运行；未发布。

本分支另行修正两处已确认的界面问题：普通 mpv 通知不再变成标题旁的警告，空态“打开文件”改用半透明描边样式。这两处修正不等于隐私功能已交付。

## 1. 已确认的要求

- 名称统一为“一键隐私模式”，不使用“一键公共场合模式”。
- 一键开启立即生效，无需重复验证 PIN；手动关闭、修改受限时段、修改保护名单或 PIN，需要验证 4 位数字 PIN。
- 手动开关优先于当前日程，不能被定时轮询立刻改回。下一次受限周期触发后，由日程重新接管。
- 进入受限时段时，已经打开的受保护影片也必须暂停并隐藏画面，包括多宫格；不能只阻止之后打开影片。
- 隐私保护解除后不自动恢复播放。
- 这是受保护内容的访问和画面控制，不是无痕播放：不删除已有历史、进度、标记或视频文件。

## 2. 方案选择

| 方案 | 取舍 |
| --- | --- |
| 只隐藏界面或列表 | 改动少，但快捷键、自动连播和原生视频子窗口可能绕过；不采用。 |
| 每次保护都关闭并重新打开影片 | 容易停止播放，但会破坏当前会话、进度和多宫格；仅作为暂停失败时的兜底，不作为正常流程。 |
| 统一策略 + 播放入口检查 + 真正隐藏视频表面 | 推荐。时间、手动开关和 PIN 只产生一个有效策略，所有媒体会话使用它，保留暂停状态和进度。 |

不把新增逻辑集中堆入 `app.rs`。时段计算、PIN/持久化、播放准入和界面投影分别隔离，能够独立测试。

## 3. 保护对象与边界

### 3.1 标记方式

- 本期采用逐个媒体条目的“设为受保护 / 取消保护”，入口覆盖当前影片、播放列表和历史条目。
- 支持本地文件和已支持的播放 URL；不自动识别影片内容，不扫描整个磁盘，不加入目录继承规则。
- 本地文件使用规范化的绝对路径；可读取时解析真实路径以合并相对路径、短路径和符号链接别名。Windows 按文件系统通常的大小写不敏感语义匹配。
- URL 使用规范化的 scheme、host 和默认端口；保留路径大小写及查询参数，不为判定保护状态发起网络请求。同一内容换用其它 URL 或访问参数时，需要重新标记。
- 隐私专用标识不改写已有历史/标记的数据键。文件在应用外改名或移动后，可能需要重新标记。
- 修改保护名单先验证 PIN。正在播放的条目被加入名单、且当前隐私模式开启时，立即执行保护转换。

### 3.2 明确不承诺的能力

- 不加密原视频或现有历史数据库，不提供磁盘无痕、文件系统访问控制或系统级防截图。
- 有本机文件/系统权限的人仍可改配置、换播放器或直接访问文件；4 位 PIN 是应用内防误开、防随意解除保护的措施，不是保险库密码。
- 实时控制范围是当前应用进程的全部单视频、网格及相关窗口。其他独立进程在启动时读取同一配置并各自执行日程；本期不增加跨进程即时广播协议。
- 不自动发布新版本，不移动已经发布的 `v0.0.1` tag，不纳入工作区已有的旧安装器未提交改动。

## 4. 日程与手动覆盖

### 4.1 日程表示

- 按系统本地时间设置星期和 `HH:mm` 起止时间，支持多条规则和跨午夜。
- 每段采用 `[开始, 结束)`；开始等于结束视为无效输入，不隐含“全天”。跨午夜规则的星期指开始当天。
- 重叠或相接的区间合并为连续受限周期，避免同一连续时段中反复触发。
- 默认不启用日程，直到用户设置 PIN 并保存时段。无有效日程时，只按手动开关运行。
- 夏令时重复时刻：开始取较早的有效时刻，结束取较晚的有效时刻；不存在的时刻顺延到之后首个有效时刻，空区间不触发。

### 4.2 本设计对“下一次周期”的明确解释

**手动覆盖到下一次合并后受限周期的“开始”失效，不是在当前时段结束时失效。**

例如每天 09:00–18:00 受限：

| 操作 | 结果 |
| --- | --- |
| 10:00 输入 PIN，手动关闭 | 保持关闭；10:01 的轮询不能重新开启，今天 18:00 也不撤销覆盖；次日 09:00 自动重新开启。 |
| 20:00 手动开启 | 不因当前处于非受限时间而关闭；次日 09:00 交回日程，仍为开启；随后 18:00 才按日程解除。 |
| 手动覆盖期间再次点击开关 | 使用新的手动状态，重新记录下一次周期开始点；关闭仍需 PIN。 |
| 没有下一次日程触发点 | 手动状态持续有效，直到用户再次操作或设置新的日程。 |

状态只需表达 `Automatic`、`ManualOn`、`ManualOff`，另存手动覆盖的失效触发点。有效状态由策略统一计算，UI 不自行用“当前是否在时段内”覆盖手动选择。

### 4.3 重启、时间变化与日程编辑

- 手动覆盖及失效点持久化。重启时若尚未跨过触发点，保留手动状态；若已跨过，清除覆盖，重新按当前日程计算。
- 日程编辑需要 PIN；有手动覆盖时，保存新日程会重新计算其下一个未来触发点，不因为普通轮询清除覆盖。没有手动覆盖时，保存后立即应用新日程。
- 正常运行时每秒核对策略，并在唤醒、窗口重新显示、打开/恢复播放和输出新画面前重新检查，不能只靠一次定时回调。
- 对时钟跳变重新计算；不修改系统时间，也不承诺对抗具有系统权限的恶意改时钟行为。
- 自动日程结束无需弹 PIN，因为日程本身已经过 PIN 授权；但只解除限制，不自动播放。手动覆盖尚有效时，日程结束不改变手动状态。

## 5. PIN 规则

- 首次配置保护功能时，在应用里输入并确认 4 个 ASCII 数字，支持前导零；没有默认 PIN，也不要求用户在聊天中提供 PIN。
- 保护名单或日程建立前必须先完成 PIN 设置。配置完成后，一键开启不再要求 PIN。
- 手动关闭、进入可编辑的保护设置、变更名单/日程、修改 PIN，都需要验证。修改 PIN 还需旧 PIN 验证和新 PIN 二次确认。
- 只保存带独立随机盐的 Argon2id 校验值，不保存明文 PIN；不复用更新签名密钥。
- 连续 5 次错误后冷却 30 秒。失败计数和冷却状态持久化，重启不能立即清除冷却；界面显示剩余等待时间。
- 校验和哈希计算放在后台，不阻塞 UI；结果绑定请求编号和策略版本。新的周期、再次开启保护或取消对话框使旧的解锁结果失效。
- 解锁授权限于本次操作或当前设置窗口；关闭窗口、应用失去焦点或退出后清除授权。再次开启保护或新的受限周期也会撤销设置窗口授权并隐藏敏感内容。
- 取消或输错 PIN 均保持原保护状态；不提供免密关闭、通用 PIN 或绕过旧 PIN 的重置按钮。
- PIN 输入和校验值不得写入日志、错误文本、诊断截图或测试产物；测试只使用明确的虚构 PIN。

## 6. 对正在播放内容的处理

### 6.1 进入保护的顺序

触发源包括手动开启、日程周期开始、恢复运行后发现已受限、以及把当前影片加入保护名单。

1. 先更新共享准入策略，阻止新的受保护打开、恢复和截图请求。
2. 对已经打开、正在加载、播放或暂停着的受保护会话，关闭其可见性许可、清除界面保存的画面，并启用临时静音。
3. 隐藏实际的原生视频窗口，或停止向 Slint 合成表面提交画面；显示不包含片名的保护占位。
4. 下发幂等的 `SetPaused(true)`，不能使用 `TogglePause`，避免把本已暂停的影片反而播放。
5. 保留媒体定位、进度及用户原有音量/静音设置。保护用静音是独立原因，不改写用户默认音量；有效静音为“用户静音或保护静音”，解除后采用用户当前偏好，不用过期快照覆盖其调整。

正常运行下在下一次策略处理时完成转换，不等待用户再次打开影片。关闭保护后撤去保护用静音/遮挡，但保持暂停；恢复播放必须是新的明确用户操作。

如果暂停失败，继续保持遮挡和静音，并停止/卸载该受保护会话作为兜底，不回到可见播放状态。兜底卸载前保留会话定位和进度快照，用户以后显式恢复时仍走正常准入检查。保存进度失败也不能导致画面重新暴露。

### 6.2 原生窗口和多宫格

- 原生视频子窗口可能绘制在 Slint 之上，不能仅靠一个 Rectangle 遮盖。
- 普通弹窗遮挡、隐私遮挡等原因独立管理；关掉菜单或设置窗口只能解除自己的遮挡原因，不能解除隐私保护。
- 延迟执行的 `show`、布局同步、全屏切换和渲染回调都要读取最新可见性许可。旧的排队显示操作不能在锁定后把画面重新打开。
- macOS 保留“干净事件循环回合执行窗口变更”的约束，不能重新引入持有运行状态借用时同步触发 AppKit 回调的问题。
- 多宫格逐条判断：受保护格子暂停并隐藏，普通格子继续；不能用一个全局布尔量误停全部影片。
- 隐私占位必须完全不透明，不采用模糊原画面或半透明遮挡；半透明样式只用于空态打开按钮等普通控件。

## 7. 防止播放入口绕过

不能只检查“打开文件”按钮。以下入口统一接入同一个准入判断：

- 文件选择、URL 打开、拖放、命令行、历史/最近打开、播放列表选择、网格新增。
- 下一项、上一项、结束后连播、当前循环和列表循环。
- 恢复播放、快捷键、逐帧和截图等可能输出受保护内容的命令。

`AppSession` 的打开路径在修改当前媒体、队列和轨道状态前先校验；后端发送层再作防守。自动连播遇受保护条目时停止并给出泛化提示，不偷偷跳过或自动解除模式。

被拒绝的打开请求不会在关闭隐私模式后自动重放；用户再次选择播放。这样也避免旧 PIN 请求完成后开启已经失效的媒体请求。

## 8. 界面和信息展示

- 菜单/按钮名称为“一键隐私模式”，同时提供可配置的快捷键动作，不抢占已有快捷键的默认绑定。
- 显示当前来源：自动时段、手动开启、手动关闭及下一次接管时间；开关反映有效状态。
- 独立 PIN/隐私设置窗口，避免被原生视频窗口遮挡；先执行保护，再展示解锁对话框。
- 除下述已授权的隐私设置窗口外，受保护条目在隐私模式下用统一占位显示；标题栏、列表副标题、工具提示、无障碍标签、字幕和时间/章节信息不能继续暴露片名或路径。
- 已通过 PIN 的隐私设置窗口可以在授权期间查看和修改保护名单，但不因此解锁视频或其它窗口；窗口失焦、关闭、再次保护或下一周期触发时清除授权和敏感展示。
- 对受保护条目的复制路径、系统定位、截图等入口暂不提供；普通条目保持原行为。
- 显示层脱敏不删除或改写历史、字幕偏好及标记数据；解除后可恢复正常展示，但不自动播放。
- 中英文文案一致；PIN 输入时不会把数字、空格或回车转发成播放器快捷键。

## 9. 持久化与异常

- 独立保存到 `AppPaths.config_dir/privacy.toml`，带 schema 版本；保存 PIN 校验值、保护名单、日程、手动覆盖及冷却状态。
- 使用临时文件和原子替换，避免一次写入失败留下半个配置。不得顺手改写旧历史数据或更新签名设置。
- 开启保护时先保证当前进程隐藏/暂停，再处理落盘失败并提示；涉及放行的关闭/取消保护/降低限制操作，保存成功之前不放行。
- 首次不存在配置时为未配置状态；已存在但损坏、版本未知或 PIN 校验信息不可读时，不静默恢复成无保护默认值，不覆盖原文件，保持受限并提示修复。
- 正常退出和重启更新的保存流程包含隐私状态；有未完成的安全状态写入时不能悄悄退出并丢掉保护。

## 10. 模块边界与现有接线

| 单元 | 职责与依赖 |
| --- | --- |
| `yoyo-core::privacy` | 保护标识、日程和手动覆盖的纯策略计算；通过传入时钟测试，不依赖 Slint/libmpv。 |
| 播放准入 / `AppSession` | 所有打开、连播和恢复路径共用策略；增加幂等暂停入口，不把权限检查散落在按钮里。 |
| desktop 隐私协调器 | UI 主线程状态转换、PIN 后台验证、计时与持久化、请求版本过滤；`app.rs` 仅作必要接线。 |
| 隐私视图投影 | 从原始播放/历史状态生成脱敏展示，不破坏存储中的数据。 |
| 视频可见性控制 | 单视频、网格、合成纹理和原生窗口共用可见性许可，阻止延迟显示和弹窗关闭后的泄露。 |
| 独立 Slint 窗口 | PIN 设置/验证、时段编辑和保护名单管理；不处理底层调度或媒体安全决策。 |

## 11. 验收标准

### 策略与 PIN

- 覆盖周期开始/结束、跨夜、星期、重叠区间、无日程、手动开/关、重启和错过触发点。
- 明确验证“手动关闭不会被当前周期轮询重开”，以及“当前周期结束不撤销手动开启”。
- 四位 PIN/前导零、错误次数冷却、取消、落盘失败和过期校验结果均有测试；磁盘和日志无明文 PIN。

### 播放与显示

- 正在播放的受保护样例跨入时段后暂停、静音且实际画面消失；原先已暂停的条目不得被切成播放。
- 普通样例不受影响；多宫格受保护格子隐藏，普通格子继续推进。
- 弹窗打开/关闭、轮询布局、全屏/窗口切换和排队显示不能重新露出受保护画面。
- 拖放、历史、命令行、自动连播、恢复/截图均不能绕过策略。
- 解除保护不自动播放，不损坏进度、历史或原有音量。
- 视觉验收先证明样例在保护前有可见画面且正在播放，再验证保护后隐藏，避免用本来就黑屏或没有播放来冒充成功。

### 验证边界

- 使用可控时钟和虚构媒体/PIN，不修改用户系统时间，不读取真实受保护影片。
- Windows 本机与 macOS ARM/Intel、Linux 原生环境分别验证各自的视频表面；未运行的平台明确标为未验收。
- 正式构建不接受关闭 PIN、替换时钟或绕过准入的测试环境变量；测试辅助入口必须隔离且不能进入正式包。
- 本文件审阅通过后再编写隐私功能的实施计划并进入 TDD；在此之前，不把设计稿称为隐私功能已经实现。
